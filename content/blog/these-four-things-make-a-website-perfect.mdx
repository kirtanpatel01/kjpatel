Have you ever opened a website that works perfectly, looks decent, and still feels… slightly wrong?

I've run into this more times than I can count.

Usually, the problem isn't a broken component or a bad color. It's the small things. A heading sits a little too far from its paragraph. Two cards use different gaps for no real reason. A section starts at a different point than the one above it. The same kind of text suddenly has a different size somewhere else.

None of these things ruin a website on their own. Together, they make it feel unfinished.

For me, four things have the biggest impact:

1. **Spacing**
2. **Typography**
3. **Grid & Alignment**
4. **Color System**

They sound basic. They are. But getting the basics right is harder than it looks.

## 1. Spacing

Good spacing is something you usually don't notice.

Bad spacing is impossible to ignore.

The easiest way to keep spacing under control is to stop picking random numbers every time something feels too close or too far apart. Pick a small scale and reuse it.

A 4px or 8px-based system is a good starting point. You might end up using values like 8, 16, 24, 32 and 48px most of the time.

The exact numbers aren't the important part. **Consistency is.**

If three similar cards have three different internal gaps, the interface starts to feel messy even when everything else is right.

Think about spacing at a few levels:

- Space between sections
- Space between components
- Space between a heading and its content
- Small gaps between related elements

You don't need twenty different spacing values. You need a few that you can use confidently.

## 2. Typography

Typography is more than choosing a nice font.

It controls how people read your interface and where their eyes go first.

One of the easiest mistakes to make is styling text based on where it appears instead of what it is.

A heading should have a heading style. Body text should have a body style. Metadata should have a quieter style.

I like thinking of typography as a small set of roles:

- **Display** — large, attention-grabbing headlines
- **Heading** — section and component titles
- **Body** — normal reading text
- **Caption** — metadata and supporting information

Each role should have its own size, weight, font and line height.

Line height matters too. Large headlines usually look better with tighter leading, while paragraphs need more room between lines.

The goal isn't to make every piece of text look different.

It's the opposite.

**Similar things should look similar.**

## 3. Grid & Alignment

A page can have great typography and spacing and still feel messy if nothing lines up.

That's where the grid comes in.

You don't always need a literal 12-column CSS grid. The important thing is having a layout structure that gives your sections shared alignment points.

Look at the left edge of your headings, text blocks, images and cards.

Do they line up?

Do sections feel like they're part of the same page, or does every section look like it was built independently?

That's what I think about when I hear "grid."

For larger layouts, a 12-column grid is useful because it gives you plenty of ways to divide the page. But it isn't a rule you need to force everywhere.

The real rule is simpler:

**Give your layout structure, then stay consistent with it.**

If one split section is 4/8 and another is 6/6, that's fine when there's a reason for it. Switching layouts randomly just because something "looked better" usually creates visual drift.

## 4. Color System

Color is where a lot of interfaces slowly become inconsistent.

You start with a few colors. Then a slightly darker gray gets added for some text. Another gray appears for a border. Then a new blue is added for a button.

After a while, nobody really knows which color is supposed to be used where.

A color system fixes that by giving colors jobs.

Instead of thinking only in hex codes, think in roles:

- Background
- Primary text
- Secondary text
- Border
- Accent
- Destructive / status colors

These can then become semantic tokens in your code.

For example, instead of scattering the same hex value throughout your components, you can use something like `--background`, `--foreground`, `--muted`, `--border` and `--primary`.

This becomes especially useful when you introduce dark mode or change the visual identity later.

The other important part is contrast.

Not everything on the page needs the same visual weight. Headings should stand out. Supporting text can be quieter. Borders usually need even less attention.

**Color should help establish hierarchy, not compete for attention.**

## The Part That Actually Matters

None of these four ideas are complicated.

The difficult part is applying them consistently.

A polished website doesn't necessarily have more design elements. In many cases, it has fewer decisions being made repeatedly.

The same spacing values.

The same text roles.

The same alignment logic.

The same color roles.

That's what makes a website feel intentional.

And once you start looking for these four things, you'll notice them everywhere.
